# Altox Heater

Минималистичное Android-приложение для управления отопителем Webasto через GSM-модуль
**Altox WBUS-6** (и совместимые WBUS-4/5) по SMS. Интернет и аккаунты не нужны.

- Одна круглая кнопка: **Пуск** → «Запуск...» → после подтверждения «Нагрев запущен», кнопка
  становится **Стоп**, а шкала времени работы показывает, сколько осталось
  (`Осталось 03 мин : 12.5 сек`); выключение так же.
  По кольцу кнопки идёт прогресс: отправка SMS, отсчёт до запроса статуса, ожидание ответа.
  Цвета: зелёный — выключен, оранжевый — ждём, красный — греет, серый — не настроено.
- Время работы выбирается ползунком под кнопкой (10–15 через минуту, 17, 20, 25 … 50 через 5,
  60, 70, 80, 90, 100, 120 мин) и всегда передаётся явно.
- **Статус** (кнопка справа внизу): температура ОЖ и салона, бортсеть, пламя.
- **Настройки**: номер SIM-карты модуля (вручную или из контактов), SIM-слот телефона для отправки, пароль модуля,
  задержку опроса отопителя после отправки команды пуска или остановки (ползунок 3–60 с, 6 с),
  сколько ждать ответа модуля (60 с), периодический опрос во время нагрева — 1–20 опросов за цикл,
  поровну между статусом при пуске и в конце (рядом видно, раз в сколько это для текущего цикла):
  свежие температуры и бортсеть; если отопитель выключится раньше срока, приложение это покажет.
  Настройки, изменённые во время нагрева, действуют сразу: следующие опросы идут по новой сетке
  от начала нагрева, без немедленной SMS.
- Когда время работы истекает, приложение запрашивает статус: подтверждает, что отопитель
  выключился, и показывает температуру, на которой он закончил.

SMS с модулем остаются в обычных «Сообщениях» (удалять их или отмечать прочитанными может
только SMS-приложение по умолчанию), там же их история. Чтобы не мешали, отключите уведомления
для переписки с номером Altox.

## Протокол

| Действие | SMS                          |
|----------|------------------------------|
| Пуск     | `START:XX` (XX = 10–120 мин) |
| Стоп     | `STOP`                       |
| Статус   | `STATUS`                     |

Если на модуле задан пароль (`PASS:XXXX`), он дописывается перед командой.

Ответ на `STATUS` (WBUS-6):

    HEATER OFF
    GSM (0-31): 28
    VOLTAGE: 12.9V
    HEATER: 7C        температура ОЖ
    SENSOR: 9C        температура салона
    FLAME: NO
    OUTPUT: OFF       выход OUT (обычно светодиод в салоне)

На `START` и `STOP` модуль не отвечает, поэтому после команды приложение само шлёт `STATUS`,
пока не увидит нужное состояние. `HEATER ON` / `HEATER OFF` модуль показывает сразу (пламя и
продувка идут потом), поэтому обычно хватает одного запроса: через 6 с после команды (настраивается).
Если состояние ещё не то, запрос повторяется каждые 12 с, ещё до 50 с.
Остальные тайминги собраны в начале `Heater.kt`.

## Если закрыть приложение посреди операции

Операция доводится до конца и без открытого экрана: состояние хранится в файле настроек
приложения, ответы Altox принимает обработчик SMS, а запросы `STATUS` и таймауты будит
системный будильник. Результат виден, когда приложение снова открыто.

На Xiaomi/Redmi (MIUI, HyperOS), Huawei, Honor и некоторых других телефонах смахивание из
недавних полностью останавливает приложение: тогда оно не получает SMS и не просыпается по
будильнику. Включите для него «Автозапуск» и снимите ограничения батареи («Без ограничений»).

## Сборка

JDK 17, Android SDK (platform 36, build-tools 36.1.0), Gradle 8.14:

    gradle assembleDebug   # отладочная: app/build/outputs/apk/debug/app-debug.apk
    ./build.sh             # подписанная релизная: dist/altox-heater-<версия>.apk

Для `build.sh` нужен свой ключ: `release.jks` в корне проекта и его пароль в `secrets.env`
(`ANDROID_KEYSTORE_PASSWORD=...`). Оба файла в git не попадают, команда создания ключа есть в `build.sh`.

Тесты (на JVM через Robolectric, эмулятор не нужен):

    gradle testDebugUnitTest

Они разбирают реальные ответы модуля и проводят экран через пуск, остановку, запрос статуса и
отказы, подставляя ответы Altox и сдвигая время. Скриншоты экранов сохраняются в `app/build/screenshots/`.

Разрешения: SEND_SMS, RECEIVE_SMS, READ_PHONE_STATE (только для списка SIM-карт),
USE_EXACT_ALARM (запросы статуса вовремя при закрытом приложении).
